# AI Usage Info

## Zweck

PHP-Library für die OpenAI Responses API (`POST /v1/responses`) ohne zusätzliche HTTP-Dependencies. Hauptnutzung sind die globalen `phore_ai_*`-Funktionen. Für zusammenhängende Abläufe steht `AiContext` zur Verfügung; die bisherige `PhoreAi`-Fassade bleibt als niedrigerer Einstieg erhalten. Unterstützt GPT-5-Modelle und neuer;
Unterstützt serialisierung / hydration von DTOs, Bildgenerierung, Audio-Input und multiprompting mit strukturierten Daten.
Nutzt phore/schema zur schema-generierung, validierung und hydrierung von DTOs.

## Schnellstart: zuerst die Function-Calls

Für einen einzelnen Request ist die globale Function der kürzeste Einstieg:

```php
echo phore_ai_text('Schreibe ein vierzeiliges Gedicht über einen verregneten Herbstmorgen.', [
    'client' => null,
    'model' => 'gpt-5-mini',
    'reasoning' => ['effort' => 'medium'],
    'timeout' => 120,
    'connect_timeout' => 10,
    'debug_log' => true,
]);
```

Die gemeinsamen Optionen werden hier bewusst einmal vollständig gezeigt. In
normalem Anwendungscode werden nur die tatsächlich benötigten Optionen gesetzt;
`client => null` verwendet Keystore beziehungsweise Default-Client, und ohne
explizites `reasoning` gilt `['effort' => 'low']`.

### Convenience-Functions für One-Shot-Aufgaben

Die globalen Functions sind der bevorzugte Einstieg für einzelne, voneinander
unabhängige Requests. Sie decken die komplette High-Level-API ab:

| Function | Zweck |
| --- | --- |
| `phore_ai_text()` | Text erzeugen oder vorhandenen Text bearbeiten |
| `phore_ai_do()` | Arbeitsschritt ausführen, ohne Text als Ergebnis zu benötigen |
| `phore_ai_choice()` | genau einen Wert auswählen |
| `phore_ai_choices()` | mehrere Werte auswählen |
| `phore_ai_yes_no()` | `true`, `false` oder optional `null` entscheiden |
| `phore_ai_rank()` | Werte vollständig sortieren |
| `phore_ai_score()` | Score von `0.0` bis `1.0` erzeugen |
| `phore_ai_struct()` | DTO erzeugen |
| `phore_ai_edit_struct()` | vorhandenes DTO per Patch bearbeiten |
| `phore_ai_struct_array()` | Liste von DTOs erzeugen |
| `phore_ai_image()` | Bild erzeugen |
| `phore_ai_edit_file()` | eine oder mehrere Dateien gezielt bearbeiten |
| `get_last_ai_request()` | letzten Request dieses PHP-Prozesses lesen |
| `get_last_ai_response()` | letzte Response inklusive Usage lesen |
| `get_ai_usage_stats()` | prozessweite Request-, Token- und Kostensummen lesen |

Auch Dateien können direkt als Input an einem One-Shot-Call hängen:

```php
use Phore\AiHarness\PromptType\FilePrompt;

$answer = phore_ai_text([
    'Fasse die wichtigsten Aussagen der Datei in drei Punkten zusammen.',
    FilePrompt::fromFile('/path/to/File.pdf'),
]);
```

### Mehrere zusammenhängende Requests: funktional möglich

Mehrere Helper können denselben Conversation-State teilen. Dafür muss bei jedem
Call exakt derselbe `ai_context`-Name angegeben werden:

```php
use Phore\AiHarness\PromptType\FilePrompt;
use Phore\AiHarness\ToolType\WebAccessTool;

phore_ai_do([
    'Prüfe die Aussagen der Datei mit aktuellen Quellen im Web.',
    FilePrompt::fromFile('/path/to/File.pdf'),
    new WebAccessTool(),
], throw: true, options: ['ai_context' => 'article-review']);

$correct = phore_ai_yes_no(
    'Stimmen die zentralen Aussagen des zuvor geprüften Artikels?',
    options: ['ai_context' => 'article-review'],
);

$summary = phore_ai_text(
    'Fasse notwendige Korrekturen kurz zusammen.',
    ['ai_context' => 'article-review'],
);
```

Das funktioniert inhaltlich genauso wie ein `AiContext`. Der String ist aber
nur eine lose Verbindung: Ein Tippfehler oder ein später geänderter Name erzeugt
einen anderen Context. Für mehrere aufeinander aufbauende Requests ist deshalb
das Context-Objekt übersichtlicher und robuster.

### Derselbe Ablauf mit AiContext

```php
use Phore\AiHarness\AiContext;
use Phore\AiHarness\PromptType\FilePrompt;
use Phore\AiHarness\ToolType\WebAccessTool;

$context = new AiContext(prompts: [
    FilePrompt::fromFile('/path/to/File.pdf'),
    new WebAccessTool(),
]);

$context->do('Prüfe die Aussagen der Datei mit aktuellen Quellen im Web.', throw: true);
$context->setCheckpoint('verified');

$correct = $context->yesNo('Stimmen die zentralen Aussagen des zuvor geprüften Artikels?');
$summary = $context->text('Fasse notwendige Korrekturen kurz zusammen.');
```

Ab hier verwendet diese Dokumentation für mehrstufige Abläufe nur noch
`AiContext`. Die globalen Functions delegieren auf dieselben Operationen; sie
müssen deshalb nicht parallel noch einmal erklärt werden.

### Conversation-State, Checkpoints und Sessions

`AiContext` hält den Provider-Cursor zwischen Calls. `setCheckpoint()` merkt
einen Cursor, `rollback()` springt auf ihn zurück und `clone $context` erzeugt
einen unabhängigen Gesprächszweig. Rollback betrifft nur den Conversation-State:
Dateiänderungen, Tool-Nebenwirkungen und bereits angefallene Kosten werden nicht
zurückgesetzt.

Für einen Chat über mehrere HTTP-Requests kann der State beispielsweise in einer
PHP-Session gespeichert werden. Der vorbereitete Prompt-/Tool-Stack muss beim
Import identisch wieder aufgebaut werden:

```php
session_start();

$context = new AiContext(prompts: [new WebAccessTool()]);
if (isset($_SESSION['ai_state'])) {
    $context->importState($_SESSION['ai_state']);
}

$answer = $context->text($userMessage);
$_SESSION['ai_state'] = $context->exportState();
```

Der exportierte State enthält nur Provider-/Cursor-Metadaten und Checkpoints,
nicht Prompts, Tools, Client oder Modell. Provider- und Setup-Mismatches werfen
standardmäßig `ResumeStateException`; `ResumeOptions::ON_MISMATCH_RESTART` kann
bewusst einen Neustart ohne importierten Cursor wählen. Der Remote-State bleibt
providerabhängig und ist nicht unbegrenzt verfügbar.

### Callbacks im Context

`CallbackTool` ist ein normales Tool im vorbereiteten Context. Dadurch steht es
für `do()`, Text-, Datei-, Struct-, Struct-Array- und Bildoperationen zur
Verfügung:

```php
use Phore\AiHarness\ToolType\CallbackTool;

$context = new AiContext(prompts: [
    new CallbackTool(
        static fn (string $customerId): array => ['customerId' => $customerId, 'status' => 'active'],
        name: 'load_customer',
        description: 'Load the current customer record.',
    ),
]);

$context->do('Lade Kunde C-1001 und merke die relevanten Fakten.', throw: true);
$answer = $context->text('Welchen Status hat der Kunde?');
```

Nur `RecoverableToolException` wird als korrigierbares Tool-Feedback an das
Modell zurückgegeben. Andere Callback-Exceptions brechen den Lauf ab. Pro
Invocation gelten insgesamt höchstens fünf Callback-Runden.

### Context-Methoden im Überblick

| Methode | Zweck |
| --- | --- |
| `$context->do()` | internen Arbeitsschritt ausführen |
| `$context->text()` | Text erzeugen oder bestehenden String bearbeiten |
| `$context->file()` | eine oder mehrere Dateien bearbeiten |
| `$context->struct()` | DTO erzeugen oder vorhandenes Objekt patchen |
| `$context->structArray()` | DTO-Liste erzeugen |
| `$context->image()` | Bild erzeugen |
| `$context->choice()` / `choices()` | einen oder mehrere Werte auswählen |
| `$context->yesNo()` | boolesche Entscheidung, optional `null` |
| `$context->rank()` | Werte sortieren |
| `$context->score()` | Wert von `0.0` bis `1.0` erzeugen |
| `$context->setCheckpoint()` / `rollback()` | Conversation-Cursor markieren beziehungsweise zurücksetzen |
| `$context->exportState()` / `importState()` | Conversation-State zwischen Requests persistieren |

Per-Call-Options überschreiben die Defaults des Context nur für diesen Aufruf.
`AiOptions` ist optional und sinnvoll, wenn gemeinsame Optionen als typisiertes
Anwendungsobjekt weitergereicht werden sollen; für normale Beispiele reicht das
Options-Array direkt am Call beziehungsweise Constructor.

## Operationen im Detail mit AiContext

Ab hier wird nur noch die Objekt-API gezeigt. Die gleichnamigen globalen
Functions delegieren auf dieselben Operationen.

### Text erzeugen oder bearbeiten

```php
$generated = $context->text('Schreibe einen kurzen Einführungstext.');
$edited = $context->text(
    'Korrigiere nur die Rechtschreibung.',
    input: 'Herzlich wilkommen in unserer Praxis.',
);
```

`input: null` erzeugt neuen Text. Jeder gesetzte String, auch `''`, ist ein
Bearbeitungsziel. Text-Edits verwenden exakte `search`/`replacement`-Paare
gegen denselben Originalstand. `search: null` bedeutet vollständiges
Neuschreiben und muss die einzige Operation für dieses Ziel sein.

### Dateien als Quelle und Dateien als Ziel

`FilePrompt` und `file()` haben unterschiedliche Aufgaben:

- `FilePrompt::fromFile(...)` hängt eine Datei als Quellmaterial an einen
  Request. Die Datei wird gelesen, aber nicht verändert.
- `$context->file(...)` bearbeitet die explizit übergebenen Dateipfade.

```php
use Phore\AiHarness\PromptType\FilePrompt;

$context = new AiContext(prompts: [
    FilePrompt::fromFile('/path/to/specification.pdf'),
]);

$answer = $context->text('Welche drei Anforderungen sind am wichtigsten?');

$summary = $context->file(
    'Korrigiere Rechtschreibung und Zeichensetzung.',
    ['/path/to/intro.md', '/path/to/contact.md'],
);
```

Die Signatur der Schreiboperation ist:

```php
public function file(
    string|PromptType|ToolType|array $prompts,
    string|array $input,
    array $options = [],
): object|string;
```

`$input` enthält einen Zielpfad oder eine Liste von Zielpfaden, nicht den
Dateiinhalt. Vorhandene UTF-8-Textdateien werden als Quelldaten angehängt.
Fehlende Dateien können in einem vorhandenen Verzeichnis neu angelegt werden;
unlesbare Dateien führen zu einem Fehler und werden nicht als leer behandelt.

Mehrere Ziele können in einem `write_files`-Batch geändert werden. Ein
ungültiger Edit lässt die betroffene Datei vollständig unverändert; erfolgreiche
Änderungen an anderen Dateien bleiben bestehen. Das ist keine
Cross-File-Transaktion. Offene Teilfehler stehen in
`FileEditException::$files`.

Optional kann `options['output_class']` eine Klasse für eine strukturierte
Zusammenfassung der Änderung angeben. Diese Rückgabe beschreibt die Operation,
nicht den neuen Dateiinhalt.

### Structured Output mit struct()

Mit einem Klassennamen erzeugt `struct()` eine neue Instanz dieser Klasse:

```php
final readonly class Article
{
    public function __construct(
        public string $title,
        public string $summary,
    ) {}
}

$article = $context->struct(
    'Erzeuge Titel und kurze Zusammenfassung.',
    Article::class,
);
```

Die Signatur ist:

```php
public function struct(
    string|PromptType|ToolType|array $prompts,
    string|object $input,
    array $options = [],
): object;
```

Ein Klassename bedeutet Generierung. Ein bereits vorhandenes Objekt bedeutet
gezielte Bearbeitung per JSON Patch:

```php
$edited = $context->struct(
    'Kürze nur den Titel.',
    $article,
);
```

Das ursprüngliche Objekt bleibt unverändert; die Methode liefert eine neue
Instanz. Für Objekt-Patches gelten Schema-, Hash- und Patch-Prüfungen. Es gibt
keinen automatischen Full-Rewrite-Fallback. Relevante Patch-Optionen sind unter
anderem `addressing`, `expected_hash`, `dry_run` und `return_patch`;
Details stehen in [`docs/struct-patch.md`](docs/struct-patch.md).

Vorbereitete Context-Tools stehen auch bei `struct()` zur Verfügung. Nur Tools,
die zusätzlich direkt an genau diesen Objekt-Patch übergeben werden, sind in
diesem Modus nicht erlaubt.

### Listen strukturierter Ergebnisse mit structArray()

```php
$articles = $context->structArray(
    'Erzeuge drei Artikelvorschläge.',
    Article::class,
);
```

`structArray()` hydriert jedes Listenelement als Instanz der angegebenen
Klasse und liefert `list<Article>`. Eine leere Modellantwort ist als leere
Liste `[]` zulässig.

Die Signatur ist:

```php
public function structArray(
    string|PromptType|ToolType|array $prompts,
    string $input,
    array $options = [],
): array;
```

### Bilder erzeugen

```php
$image = $context->image('Erzeuge ein schlichtes Raketen-Icon.', [
    'size' => '1024x1024',
    'output_format' => 'png',
    'quality' => 'medium',
    'background' => 'transparent',
]);

$image->saveToFile('/path/to/rocket.png');
```

`image()` liefert ein `ImageResultType`. Die Datei wird nicht automatisch
gespeichert; das geschieht erst über `saveToFile()`. Relevante
Image-Optionen sind `size`, `output_format`, `quality` und `background`.
Ein bereits explizit mitgegebener `ImageGenerationTool` behält seine eigenen
Generation-Settings.

### Simple Types

Für kleine Entscheidungen ist kein DTO nötig:

```php
$tag = $context->choice('Welcher Tag passt?', ['news', 'guide', 'review']);
$tags = $context->choices(null, ['news', 'guide', 'review'], min: 1, max: 2);
$ready = $context->yesNo('Ist der Entwurf fertig?', allowNull: true);
$ranking = $context->rank('Nach Relevanz sortieren.', ['news', 'guide', 'review']);
$score = $context->score('Wie gut passt der Entwurf zur Zielgruppe?');
```

`prompt: null` verwendet den kurzen Default-Prompt der jeweiligen Methode.
`allowNull: true` erlaubt `null`, wenn der vorhandene Context ausdrücklich
nicht für eine verlässliche Entscheidung reicht. `choice()` und `choices()`
akzeptieren Listen oder `Wert => Beschreibung`-Maps; `choices()` unterstützt
`min`, `max` und optional `selected` in den Per-Call-Options.

### Preferred: Prompts aus Dateien

Für wiederverwendbare Prompt-Dateien ist `PromptFile` der bevorzugte Typ:

```php
use Phore\AiHarness\AiContext;
use Phore\AiHarness\PromptType\PromptFile;

$context = new AiContext(prompts: [
    new PromptFile(__DIR__ . '/prompts/review.prompt.md'),
]);
$result = $context->text('Führe den Review aus.');
```

`PromptFile` bedeutet, dass die Datei den Prompt selbst definiert. `FilePrompt`
hingegen hängt eine Datei als Quellmaterial an einen Prompt. `TextPrompt`,
`FilePrompt`, `ImagePrompt`, `AudioPrompt` und `StructPrompt` behandeln ihren
Inhalt standardmäßig als externe, unvertrauenswürdige Daten
(`allowInstructions: false`). Nur ausdrücklich freigegebene Quellen dürfen
Anweisungen aus ihrem Inhalt liefern.

`PromptFile` unterstützt YAML-Frontmatter mit `description`, `extends`,
`references` und `requires_aliases`. Relative Pfade werden immer relativ zu der
Datei aufgelöst, die den Eintrag definiert. Referenzen sind standardmäßig
untrusted und können einzeln mit `allow_instructions: true` freigegeben werden.
Das vollständige Format steht unter
[`examples/frontmatter-prompt/`](examples/frontmatter-prompt/).

## AI Toolsets

`AiToolSet` gruppiert mehrere zusammengehörige `ToolType`-Instanzen hinter
einem wiederverwendbaren, zustandsbehafteten Objekt. `AiContext` speichert pro
konkreter Toolset-Klasse höchstens eine Instanz und stellt dafür
`addToolSet()`, `hasToolSet()` und `getToolSet()` bereit.

```php
$toolSet = new ProjectToolSet();

$firstContext = new AiContext();
$secondContext = new AiContext();

$firstContext->addToolSet($toolSet);
$secondContext->addToolSet($toolSet);

assert($firstContext->getToolSet(ProjectToolSet::class) === $toolSet);
assert($secondContext->hasToolSet(ProjectToolSet::class));
```

Damit kann dieselbe Instanz bewusst als kleiner prozesslokaler Singleton für
einen oder mehrere Contexts dienen. Das ist sinnvoll, wenn mehrere Tools eine
gemeinsame Registry oder Dependency verwenden. Ein geklonter Context teilt
dieselben Toolset-Objekte. `exportState()` serialisiert Toolsets nicht; die
Anwendung baut sie vor `importState()` erneut auf.

Siehe `examples/13-tool-set.php` für ein vollständiges eigenes Toolset.

## AI File System

`AiFileSystem` ist ein kontrollierter Filesystem-Workspace, der mit einem
`AiContext` verbunden wird. Es lädt nicht vorab ganze Verzeichnisbäume in den
Prompt. Stattdessen stellt ein gemeinsames `AiFileSystemToolSet` begrenzte
Operationen zum Listing, zur Grep-Suche, zum Lesen, Editieren sowie für History
und Restore bereit.

```php
$context = new AiContext();

$fileSystem = new AiFileSystem(
    $context,
    id: 'backend',
    alias: 'Backend project',
    description: 'PHP application code and documentation.',
    policy: new FileSystemPolicy(
        ignore: ['app/vendor/*', 'app/node_modules/*', 'app/.git/*'],
        editable: ['app/src/*', 'app/docs/*'],
    ),
    revisionStore: new SqliteRevisionStore('/var/lib/app/ai-history.sqlite'),
);

$fileSystem->addRoot('/srv/backend', 'app', searchable: true, editable: true);
$fileSystem->addFile(
    '/srv/shared/architecture.md',
    'architecture',
    searchable: true,
    editable: false,
);

$context->do(
    'Find the deprecated cache adapter, update its use in app/src and update '
    . 'the matching documentation in app/docs. Do not edit architecture.',
    throw: true,
);
```

Jedes Root-Verzeichnis und jede einzeln hinzugefügte Datei erhält einen
virtuellen Top-Level-Namen. Tool-Calls verwenden zuerst die Filesystem-ID und
danach diesen virtuellen Pfad. Dadurch kollidieren gleichnamige Dateien aus
verschiedenen Projekten nicht, und reale Host-Pfade werden dem Modell nicht
offengelegt.

`searchable` steuert Listing, Read und Grep; `editable` steuert Edit und
Restore. `FileSystemPolicy` ergänzt Pattern-basierte Allowlists und ignorierte
Subtrees. Ignorierte Verzeichnisse werden bereits beim Traversieren
übersprungen. Rekursives Listing ist opt-in und paginiert; `maxListLimit`,
`maxSearchResults` und `maxReadBytes` begrenzen Tool-Ergebnisse.

Das Modell entdeckt Filesystem-IDs mit `filesystem_list_systems`, grenzt den
Arbeitsbereich mit `filesystem_list` oder `filesystem_grep` ein, liest nur die
benötigten Zeilenbereiche und ruft danach `filesystem_edit` für explizit
editierbare Ziele auf. Edits verwenden exakte `search`/`replacement`-Paare
gegen denselben Originalstand; `search=null` ist ein Full Rewrite und muss die
einzige Edit-Operation sein.

Standardmäßig sind ein Markdown- und ein generischer UTF-8-Text-Editor
registriert. Weitere `FileEditorInterface`-Implementierungen können priorisiert
hinzugefügt werden, ohne neue Tool-Namen im Context zu erzeugen. Binäre oder
ungültige UTF-8-Inhalte sind nicht editierbar.

Für Markdown liefert `filesystem_structure` die Überschriften als Baum mit
stabilen Section-IDs. `filesystem_structure_edit` kann damit ganze Sections
ersetzen, löschen, einfügen oder vor beziehungsweise hinter andere Sections
verschieben. Ein Section-Bereich umfasst seine Untersections. Nach einer
Umbenennung oder neu hinzugefügten doppelten Überschrift sollte die Struktur
neu gelesen werden, bevor eine alte ID weiterverwendet wird.

Revision-History ist optional. Mit `SqliteRevisionStore` werden Original- und
Ergebnisstand jedes Writes in SQLite gespeichert. `filesystem_history` listet
Revisionen, `filesystem_restore` stellt eine Revision wieder her und erhält
dabei die Historie. Das ist unabhängig von `AiContext::rollback()`, das nur den
Conversation-Cursor verschiebt.

Mehrere `AiFileSystem`-Objekte am selben Context registrieren sich beim bereits
vorhandenen `AiFileSystemToolSet`. Der Context erhält deshalb nur einen Satz
Filesystem-Callbacks und nicht für jedes Filesystem neue Tool-Namen.

Die vollständige Beschreibung steht in
[`docs/ai-filesystem.md`](docs/ai-filesystem.md); ein kompletter Ablauf steht in
[`examples/14-ai-file-system.php`](examples/14-ai-file-system.php).

## Wichtige Tools

Tools werden bei mehrstufigen Abläufen direkt im vorbereiteten `AiContext`
mitgegeben. Damit bleiben Tool-Verfügbarkeit und Conversation-State an einer
Stelle sichtbar:

```php
$context = new AiContext(prompts: [
    new \Phore\AiHarness\ToolType\WebAccessTool(),
    new \Phore\AiHarness\ToolType\TaskErrorTool(),
]);
```

Verfügbare Tools:

- `WebAccessTool`: OpenAI-Websuche.
- `FileSearchTool`: File Search über OpenAI Vector Stores.
- `CodeInterpreterTool`: OpenAI Code Interpreter.
- `ImageGenerationTool`: Bildgenerierung.
- `ComputerUseTool`: Computer-Use Preview.
- `McpTool`: Remote-MCP-Server oder OpenAI-Connector.
- `CallbackTool`: PHP-`callable` als OpenAI Function Tool.
- `TaskErrorTool`: strukturierter Abbruch bei fehlenden oder widersprüchlichen Voraussetzungen.
- `LocalShellTool`: OpenAI Local-Shell Tool.

`TaskErrorTool` ist bei Jobs empfehlenswert, bei denen das Modell bei fehlenden
Voraussetzungen nicht raten soll. `RecoverableToolException` ist der einzige
Callback-Fehler, der als retry-fähiges Tool-Feedback an das Modell geht; andere
Exceptions werden unverändert nach außen durchgereicht.
## Wichtige APIs

- `Phore\AiHarness\AiContext`: gemeinsamer Conversation-State für mehrere aufeinander aufbauende Requests.
- `AiContext::__construct(prompts: ..., options: ...)`: vorbereitet wiederkehrende Prompts, Tools und gemeinsame Defaults.
- `AiContext::do()`: Arbeitsschritt ohne sichtbare Textausgabe; liefert `bool` oder wirft mit `throw: true` `DoException`.
- `AiContext::text()`: Text erzeugen beziehungsweise einen gesetzten Input-String bearbeiten.
- `AiContext::file()`: eine oder mehrere explizite UTF-8-Textdateien bearbeiten.
- `AiContext::struct()` / `structArray()`: DTOs erzeugen, Listen hydrieren beziehungsweise vorhandene Objekte patchen.
- `AiContext::image()`: Bildausgabe mit den Image-Optionen des Providers.
- `AiContext::choice()` / `choices()` / `yesNo()` / `rank()` / `score()`: kleine typisierte Entscheidungen.
- `AiContext::setCheckpoint()` / `rollback()`: lokalen Conversation-Cursor markieren und wiederherstellen.
- `AiContext::exportState()` / `importState()`: Cursor und Checkpoints zwischen Requests persistieren.
- `Phore\AiHarness\AiOptions`: optionale typisierte gemeinsame Defaults für `client`, `model`, `reasoning`, `timeout`, `connect_timeout` und `debug_log`.
- `Phore\AiHarness\PromptType\PromptFile`: wiederverwendbare Prompt-Datei mit Frontmatter-Komposition.
- `Phore\AiHarness\PromptType\FilePrompt`: Datei als Quellmaterial, standardmäßig untrusted.
- `get_last_ai_request()` / `get_last_ai_response()`: letzter Request beziehungsweise letzte Response des Prozesses.
- `get_ai_usage_stats()`: prozessweite Request-, Token- und Kostensummen.

Die vollständigen Context-Verträge und Grenzen stehen in
[`docs/ai-context.md`](docs/ai-context.md).

## Optional streaming debug logging

All global helpers (`phore_ai_do`, `phore_ai_choice`, `phore_ai_choices`,
`phore_ai_yes_no`, `phore_ai_rank`, `phore_ai_score`, `phore_ai_text`,
`phore_ai_struct`, `phore_ai_edit_struct`, `phore_ai_struct_array`,
`phore_ai_image`, `phore_ai_edit_file`) and the
corresponding `AiContext` methods accept
`debug_log?: bool|\Phore\AiHarness\Logging\LoggerInterface`:

```php
$text = phore_ai_text('Summarize the status', ['debug_log' => true]);

// Direct context alternative:
$text = (new \Phore\AiHarness\AiContext())->text('Summarize the status', options: [
    'debug_log' => true,
]);

$ai = (new \Phore\AiHarness\PhoreAi())
    ->withLogger(new \Phore\AiHarness\Logging\ConsoleLogger());
```

Default/`false`: no logger, existing non-streaming behavior. `true`: console
logging to STDERR. A custom logger implements `log(LogEvent $event): void`.
Other values (including `null`) are rejected before the API call.
`withLogger()` is immutable; `withLogger(null)` disables it.

With a logger, text/structured requests and callback follow-ups stream;
images remain non-streaming. Output has `[model]` prefixes, buffered complete
lines, tool start/status/duration entries and one final `RunStatistics` event.
Terminal warnings are red unless `NO_COLOR` is set. Tool arguments and known
credential patterns are redacted before custom loggers receive them; results
are represented by byte counts, and raw exception messages are omitted.

Only an explicit `RecoverableToolException` becomes a machine-readable
`ok: false` output, identically with or without logging. All other callback
exceptions and argument decoding/validation/binding errors abort unchanged.
Correction requests count as retries; at most five callback rounds execute,
including context clarification tools. Remaining calls then raise an
exception. Task errors, transport/authentication failures, internal PHP errors
and serialization failures are not retried. Follow-up instructions, tools and
output schemas are retained in both logging modes.

`stats` contains `status`, `requests`, `tool_calls`, `errors`, `retries`,
`tokens_in`, `tokens_out`, `tokens_total`, `tokens_cached`, `duration_total`,
`duration_api`, `duration_tools`. Durations use a monotonic clock and seconds.
Tokens sum available response usage, with `null`/`n/a` if unavailable. A reported
cached-token value of zero remains `0`; cached tokens are a subset of input,
not additional tokens. The summary is emitted once in a finally path, also
for failures during request preparation or hydration.

The existing global `get_ai_usage_stats()` also exposes `cachedInputTokens`,
per-model usage and the dated cost estimate (`knownCostUsd`, nullable
`totalCostUsd`). These counters are independent of logging and are never reset
by context rollback or clone. Response chaining and prompt caching are
separate: `previous_response_id` saves repeated HTTP payloads, not context
window space or all input billing. Cache hits are provider-managed and are
not guaranteed across model changes. No cache warming is implemented.


## AiContext an Domain-Objekte binden

`Phore\AiHarness\AiContextTrait` stellt die komplette Context-API mit
`ai_*`-Prefix direkt auf einem Domain-Objekt bereit. Ein vorbereiteter Context
wird einmalig mit `ai_set_context()` gebunden oder mit `ai_prepare()`
erzeugt. Ohne Vorbereitung wird beim ersten Zugriff lazy ein leerer Context
angelegt.

Beispiele: `ai_text()`, `ai_do()`, `ai_struct()`, `ai_struct_array()`,
`ai_choice()`, `ai_choices()`, `ai_yes_no()`, `ai_rank()`,
`ai_score()`, `ai_file()`, `ai_image()` sowie die Checkpoint-/State-
Methoden `ai_set_checkpoint()`, `ai_rollback()`, `ai_export_state()` und
`ai_import_state()`. Für Content stehen außerdem
`ai_get_content_by_id()` und `ai_query_content()` bereit.

Der Context kann nicht nachträglich ausgetauscht werden. Damit bleibt ein
Domain-Objekt stabil an genau einen Conversation-Cursor gebunden.


## AI-Content-Typen

`AiDocument` ist die primäre und höchste Abstraktion für AI-verarbeitbare
Inhalte. Anwendungscode sollte nach Möglichkeit `AiDocument` verwenden und
nur dann auf `AiText`, `AiMarkdown`, `AiFrontMatter`, `AiCode`,
`AiImage`, `AiAudio` oder `AiVideo` festgelegt werden, wenn deren
spezialisierte API benötigt wird.

Der empfohlene Einstieg zur Erzeugung ist `AiDocumentFactory`. Für reale
Dateien ist `fromFile()` vorzuziehen; die Factory erkennt den Typ anhand der
Extension. `fromRaw()` ist für bereits im Speicher vorliegende Bytes gedacht
und erzeugt Dokumente aus Bytes plus explizitem `ContentType`/MIME-Type beziehungsweise
einem Dateinamen mit bekannter Extension. Dadurch benötigen Consumer wie
Mail-Anhang-Verarbeitung keine eigene Typ-Fallunterscheidung.

```php
$factory = new \Phore\AiHarness\Content\AiDocumentFactory();

$document = $factory->fromFile(
    '/path/to/lebenslauf.pdf',
    description: 'Anhang aus der aktuellen Bewerber-Mail.',
    id: 'cv',
    aliases: ['Lebenslauf', 'Bewerbungsdokument'],
);

$isCv = $document->ai_yes_no('Ist cv ein Lebenslauf?');
```

`ContentType` enthält bewusst nur die vom Harness unterstützten
OpenAI-Content-Types und bildet Extension und MIME-Type in beide Richtungen ab.
Ein explizit übergebener Content-Type hat Vorrang vor der Dateiendung.

Eigene Dokumenttypen werden auf einer Factory-Instanz mit `register()`
registriert. Nutzerregistrierungen überschreiben die eingebaute Zuordnung und
können zusätzliche Extensions bekannt machen. Der Callback muss ein
`AiDocument` zurückgeben.

Jedes `AiContent` besitzt eine eindeutige immutable ID. Wird keine ID
angegeben, erzeugt der Harness automatisch eine; sie ist über `getId()`
abrufbar. Explizite IDs müssen innerhalb eines `AiContext` eindeutig sein.
`aliases` sind optionale, nicht eindeutige Referenznamen. ID und Aliases
werden als vertrauenswürdige Metadaten an die AI gegeben und können deshalb
direkt in späteren Prompts referenziert werden. `instructions` sind
dokumentbezogene Hinweise und standardmäßig leer.

Für echte Dateien ist `fromFile()` der bevorzugte Einstieg:

```php
$factory = new \Phore\AiHarness\Content\AiDocumentFactory();

$liste = $factory->fromFile(
    '/path/to/preisliste.pdf',
    id: 'price-list-2026',
    aliases: ['Preisliste', 'Liste 123'],
);

$bild = $factory->fromFile(
    '/path/to/package.jpg',
    aliases: ['Paketfoto'],
);

$autoId = $bild->getId();

$context = new \Phore\AiHarness\AiContext(prompts: [$liste, $bild]);

$text = $context->text(
    'Vergleiche Liste 123 mit Paketfoto und nenne die relevanten Unterschiede.',
);

$text = $context->text(
    'Beschreibe das Bild mit der ID ' . $autoId . '.',
);
```

Mit `$context->getContentById($id)` wird ein konkretes Objekt ohne AI-Aufruf
aufgelöst. `$context->queryContent($prompt)` lässt die AI ausschließlich aus
den im Context registrierten IDs passende Inhalte auswählen und liefert ein
`AiContentResultSet`.

```php
$bilder = $context->queryContent(
    'Welche Bilder zeigen sichtbare Schäden am Paket?',
);

$alle = $bilder->all();
$erstes = $bilder->first();
$konkretes = $bilder->getById($autoId);

// Nur die bereits gefundenen Bilder erneut filtern.
$nahaufnahmen = $bilder->query('Welche davon sind Nahaufnahmen?');

// Neuer Conversation-Branch nur mit dem Result-Set.
$frisch = $bilder->withContext();
$zusammenfassung = $frisch->getContext()->text(
    'Fasse die sichtbaren Schäden in diesen Bildern zusammen.',
);

// Oder das Result-Set an einen bestehenden Context hängen.
$weiter = $bilder->withContext($existingContext);
```

Das Result-Set ist iterierbar und stellt zusätzlich `getContext()` bereit.
Domain-Objekte mit `AiContextTrait` haben dieselbe API über
`ai_get_content_by_id()` und `ai_query_content()`.

`AiText` ist der generische String-Container, `AiMarkdown` dessen
Markdown-Spezialisierung. `withContext($context)` liefert immer ein neues
Content-Objekt und klont den angegebenen Conversation-Branch; auch ein bereits
gestarteter Context kann so weiterverwendet werden, wobei das Dokument beim
nächsten Request einmal als Source angehängt wird. `withContext(null)` trennt
es bewusst vom bisherigen Context und bindet einen frischen Context mit dem
Dokument als Source.

`AiFrontMatter` kombiniert einen strukturierten YAML-Header mit einem
`AiMarkdown`-Body. `headerEdit()`, `bodyEdit()` und `edit()` erlauben
gezielte beziehungsweise gemeinsame Änderungen. Die `AiDocumentFactory`
erkennt YAML-Front-Matter bei Markdown automatisch. Optional kann als `headerSchema` entweder ein
`Phore\Schema\Schema\ClassSchema` oder direkt ein PHP-Klassenname übergeben
werden. Bei einem Klassennamen parst der Harness das Schema automatisch über
`phore/schema`. Typen und Feldbeschreibungen werden dadurch an die AI
weitergegeben und jeder erzeugte Header gegen dasselbe Schema validiert.

```php
$article = \Phore\AiHarness\Content\AiFrontMatter::fromFile(
    '/path/to/article.md',
    headerSchema: ArticleHeader::class,
    id: 'article',
    aliases: ['Seite', 'Artikel'],
);
```

`AiContent` bleibt immer Datenmaterial und wird nie implizit zu Instructions
hochgestuft. Nur `AiInstruction` und `SystemPrompt` dürfen in den
Instruction-Kanal des Providers.

Details und Beispiele: `docs/ai-content.md`, `examples/10-ai-content.php`,
`examples/11-front-matter.php` und `examples/12-content-query.php`.
