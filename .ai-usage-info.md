# AI Usage Info

## Zweck

PHP-Library für die OpenAI Responses API (`POST /v1/responses`) ohne zusätzliche HTTP-Dependencies. Hauptnutzung sind die globalen `phore_ai_*`-Funktionen oder die `PhoreAi`-Fassade. Unterstützt GPT-5-Modelle und neuer;
Unterstützt serialisierung / hydration von DTOs, Bildgenerierung, Audio-Input und multiprompting mit strukturierten Daten.
Nutzt phore/schema zur schema-generierung, validierung und hydrierung von DTOs.

## Schnellstart

```php
// API-Key kommt automatisch aus OPENAI_API_KEY oder /var/run/secrets/open_ai
echo phore_ai_text('Sag Hallo in einem Satz.');
```

Keystore manuell setzen:

```php
use Phore\AiHarness\Keystore\Keystore;

Keystore::instance()->addKey('sk-...', 'open_ai');
echo phore_ai_text('Sag Hallo.');
```

Structured Output:

```php
final readonly class AnswerDto
{
    public function __construct(public string $answer) {}
}

$dto = phore_ai_struct('Antworte als JSON-Objekt.', AnswerDto::class);
echo $dto->answer;
```

Structured Output als Liste:

```php
final readonly class TodoDto
{
    public function __construct(public string $title, public bool $done) {}
}

$todos = phore_ai_struct_array('Erzeuge drei kurze Todos.', TodoDto::class);
echo $todos[0]->title;
```

Bildgenerierung:

```php
$image = phore_ai_image('Erzeuge ein schlichtes Raketen-Icon auf transparentem Hintergrund.', [
    'size' => '1024x1024',
    'output_format' => 'png',
    'background' => 'transparent',
]);

$image->saveToFile(__DIR__ . '/rocket.png');
```

Eine oder mehrere Dateien bearbeiten:

```php
$summary = phore_ai_edit_file(
    'Füge am Ende der Datei eine kurze Changelog-Notiz für Version 1.2.0 hinzu.',
    __DIR__ . '/CHANGELOG.md'
);
echo $summary; // Text-Zusammenfassung oder Liste der Änderungen
```

Zusammenhängende Änderungen können in einem Request geschrieben werden. Jede Datei wird mit ihrem Dateinamen und aktuellen Inhalt an den Prompt angehängt; fehlende oder nicht lesbare Dateien werden mit leerem Inhalt übergeben.

```php
$summary = phore_ai_edit_file(
    'Aktualisiere die Versionsnummer in beiden Dateien konsistent.',
    [__DIR__ . '/composer.json', __DIR__ . '/docs/version.md'],
);
```

Datei mit mehreren Datenquellen bearbeiten: Jeder Prompt kann einen `alias` und eigene `instructions` bekommen. Andere Prompts können diese Datenquelle dann per Alias referenzieren.

```php
use Phore\AiHarness\PromptType\FilePrompt;
use Phore\AiHarness\PromptType\StructPrompt;
use Phore\AiHarness\PromptType\TextPrompt;

$customerFacts = [
    'customer' => 'ACME GmbH',
    'industry' => 'Maschinenbau',
    'goal' => 'Wartungsvertrag verlängern',
];

$summary = phore_ai_edit_file([
    new TextPrompt(
        'Aktualisiere die Zieldatei. Nutze `customerFacts` für Fakten, `styleGuide` für Tonalität und `pricingRules` für kaufmännische Regeln.',
        alias: 'editTask',
        instructions: 'Dies ist die führende Arbeitsanweisung. Erfinde keine Daten, die nicht in den referenzierten Quellen stehen.',
    ),
    new StructPrompt(
        $customerFacts,
        alias: 'customerFacts',
        instructions: 'Verbindliche Kundendaten. Diese Daten haben Vorrang vor allgemeinen Formulierungen aus `styleGuide`.',
    ),
    FilePrompt::fromFile(
        __DIR__ . '/style-guide.md',
        alias: 'styleGuide',
        instructions: 'Nur Schreibstil, Terminologie und Format übernehmen. Keine Preise oder Kundendaten daraus ableiten.',
        type: 'markdown',
    ),
    new TextPrompt(
        'Bestandskundenrabatt: 7 %. Zahlungsziel: 14 Tage netto.',
        alias: 'pricingRules',
        instructions: 'Diese kaufmännischen Regeln ergänzen `customerFacts` und dürfen nicht durch `styleGuide` überschrieben werden.',
    ),
], __DIR__ . '/angebot.md'); // Inhalt wird als Prompt angehängt; genau diese Datei wird per Callback-Tool vollständig ersetzt

echo $summary;
```

Multiprompt mit zusätzlichen Struct-Input-Daten:

```php
use Phore\AiHarness\PromptType\StructPrompt;
use Phore\AiHarness\PromptType\TextPrompt;

final readonly class SummaryDto
{
    public function __construct(public string $summary, public array $tags) {}
}

$context = [
    'customer' => 'ACME GmbH',
    'language' => 'de',
    'topics' => ['Angebot', 'Lieferzeit', 'Support'],
];

$result = phore_ai_struct([
    new TextPrompt('Erstelle eine kurze Zusammenfassung anhand der Zusatzdaten.'),
    new StructPrompt(
        $context,
        alias: 'customerContext',
        instructions: 'Nutze diese Daten als verbindlichen Kontext. Erfinde keine zusätzlichen Kundendaten.',
    ),
], SummaryDto::class);
```

PhoreAi-Fassade:

```php
use Phore\AiHarness\PhoreAi;
use Phore\AiHarness\PromptType\TextPrompt;
use Phore\AiHarness\ToolType\WebAccessTool;

$text = (new PhoreAi())
    ->withModel('gpt-5-mini')
    ->with(new TextPrompt('Recherchiere kurz PHP 8.5.'), new WebAccessTool())
    ->run();
```

## Wichtige Tools

Tools können direkt über die `with()`-Methode der `PhoreAi`-Fassade oder als Prompt-Items an die `phore_ai_*`-Funktionen übergeben werden. Empfohlen: `TaskErrorTool` sollte grundsätzlich bei Requests mitgegeben werden, damit das Modell bei uneindeutigen, widersprüchlichen oder unvollständigen Anweisungen nicht rät, sondern eine strukturierte `TaskErrorException` auslöst.

```php
use Phore\AiHarness\PhoreAi;
use Phore\AiHarness\PromptType\TextPrompt;
use Phore\AiHarness\ToolType\WebAccessTool;

$text = (new PhoreAi())
    ->with(new TextPrompt('Recherchiere kurz PHP 8.5.'), new WebAccessTool())
    ->run();
```

oder kürzer:

```php
echo phore_ai_text([
    new TextPrompt('Recherchiere kurz PHP 8.5.'),
    new WebAccessTool(),
    new TaskErrorTool(),
]);
```

Verfügbare Tools:

- `WebAccessTool`: OpenAI-Websuche (`web_search_preview`), optional mit Roh-Optionen wie `search_context_size`.
- `FileSearchTool`: File-Search über OpenAI Vector Stores, z. B. mit `vector_store_ids`.
- `CodeInterpreterTool`: OpenAI Code Interpreter, z. B. mit `container`-Option.
- `ImageGenerationTool`: Bildgenerierung; validierte Optionen `size`, `output_format`, `quality`, `background`.
- `ComputerUseTool`: Computer-Use Preview mit Optionen wie Displaygröße und Umgebung.
- `McpTool`: Remote-MCP-Server oder OpenAI-Connector. Pflicht: `server_label` und genau eines von `server_url` oder `connector_id`; optional `authorization`, `headers`, `allowed_tools`, `allowed_callers`, `require_approval`, `defer_loading`.
- `CallbackTool`: registriert ein PHP-`callable` als OpenAI Function Tool. Parameter und Return-Typ werden über `phore/schema` aus Signatur/PHPDoc gelesen; der Return-Typ wird in die Tool-Beschreibung aufgenommen.
- `RecoverableToolException`: kann in einem `CallbackTool` mit einer modellgeeigneten Fehlermeldung geworfen werden. Nur diese Exception wird als strukturiertes, retry-fähiges Tool-Feedback an das Modell geliefert; alle anderen Exceptions brechen den gesamten Lauf ab und werden an die aufrufende Programmschicht durchgereicht.
- `TaskErrorTool`: spezielles `CallbackTool`, das immer mitgegeben werden sollte. Wenn der Job wegen uneindeutiger/widersprüchlicher Prompts, fehlender Daten oder fehlender Tools/Capabilities nicht erfüllbar ist, soll das Modell dieses Tool aufrufen statt zu raten. Es wirft eine `TaskErrorException` mit zitierten widersprüchlichen Aussagen, fehlenden Daten/Tools/Informationen und dem Ort, an dem Klärung oder Zugriff angefordert werden soll.
- `LocalShellTool`: OpenAI Local-Shell Tool (`local_shell`).

Fehlersemantik für Callback-Tools:

```php
use Phore\AiHarness\ToolType\CallbackTool;
use Phore\AiHarness\ToolType\RecoverableToolException;

$readFile = new CallbackTool(static function (string $path): string {
    if (!is_file($path)) {
        throw new RecoverableToolException('File not found. Check the path and retry.');
    }

    return (string) file_get_contents($path);
}, name: 'read_file');
```

`RecoverableToolException` setzt den Chat fort, damit das Modell den Aufruf korrigieren oder einen anderen Weg wählen kann. Jede andere Exception, einschließlich `TaskErrorException`, beendet den Lauf und wird unverändert nach außen durchgereicht. Der Harness führt keinen automatischen Retry aus.

## Wichtige APIs

- `phore_ai_text($prompts, array $options = []): string`: Textausgabe. Optionen: `client`, `model`, `timeout`, `connect_timeout`.
- `phore_ai_struct($prompts, string $className, array $options = []): object`: Structured Output mit Hydration in `$className`.
- `phore_ai_struct_array($prompts, string $className, array $options = []): list<object>`: Structured Output als Liste; OpenAI gibt intern `{items: [...]}` zurück, jedes Item wird in `$className` hydriert. Leere Ergebnislisten sind erlaubt und werden als `[]` zurückgegeben.
- `phore_ai_image($prompts, array $options = []): ImageResultType`: Bildgenerierung. Optionen u.a. `size`, `output_format`, `quality`, `background`.
- `phore_ai_edit_file($prompts, string|list<string> $filenames, ?string $className = null, array $options = []): string|object`: hängt Dateiname und aktuellen Inhalt jeder Zieldatei an den Prompt (bei nicht lesbarer oder fehlender Datei mit leerem Inhalt) und lässt das Modell alle Änderungen in einem Aufruf des Callback-Tools `write_files` schreiben. Ohne `$className` wird Text zurückgegeben; mit `$className` wird Structured Output in diese Klasse hydriert. Ein gemeinsamer Request eignet sich für eng zusammenhängende, überschaubare Dateien; große oder unabhängige Dateien sollten wegen Kontextgröße und Fehlerisolation auf mehrere Aufrufe verteilt werden.
- `get_last_ai_request(): ?AiRequest`: letzter Request dieses PHP-Prozesses (`AiRequest::$last`).
- `get_last_ai_response(): ?AiResponse`: letzte Response dieses PHP-Prozesses (`AiResponse::$last`).
- `Phore\AiHarness\PhoreAi`: Fassade für Prompts, Tools, Modelle und Ausgabeformate.
- `Phore\AiHarness\Client\OpenAiClient`: CURL-Client; Timeout konfigurierbar (`timeout`, Default 600s; `connectTimeout`, Default 10s).
- `Phore\AiHarness\Client\AiResponse::getUsage(): UsageInfoType`: Tokenverbrauch und geschätzte USD-Kosten.
- `Phore\AiHarness\PromptType\SystemPrompt`: System-Instructions; der OpenAI-Converter erkennt Prompts mit `type() === 'system'` automatisch und fügt sie in das Responses-API-Feld `instructions` ein.
- `Phore\AiHarness\PromptType\DefaultSystemPrompt`: Standard-Systemprompt für Batch-Betrieb; wird automatisch eingefügt, wenn kein System-Prompt übergeben wurde. Weist das Modell an, die Aufgabe ohne User-Interaktion auszuführen, bei nicht erfüllbaren Jobs wegen uneindeutiger/widersprüchlicher Prompts, fehlender Daten oder fehlender Tools nicht zu raten und falls vorhanden `TaskErrorTool` aufzurufen. Dateien/Bilder/Audio werden standardmäßig als Quellmaterial statt als Anweisungen behandelt.
- `Phore\AiHarness\PromptType\TextPrompt`: Text-Input; optional `alias`, `instructions` und `type`/Content-Format. Wenn `type` gesetzt ist, wird der Text im OpenAI-Converter als fenced Codeblock gerendert.
- `Phore\AiHarness\PromptType\FilePrompt`, `ImagePrompt`, `AudioPrompt`: Datei-, Bild- und Audio-Input; optional `alias`, `instructions` und `type`/Content-Format. Metadaten werden als separate Text-Sektion direkt vor dem jeweiligen Segment eingefügt.
  - `FilePrompt::fromFile(string $fileName, ?string $alias = null, ?string $instructions = null, ?string $type = null): FilePrompt` liest eine lokale Datei, erkennt den MIME-Type automatisch und hängt sie als Quellmaterial an. `$alias` ist ein Referenzname für andere Prompts, `$instructions` sind dateispezifische Nutzungsregeln, `$type` beschreibt das logische Format wie `markdown` oder `csv`.
- `Phore\AiHarness\PromptType\StructPrompt`: akzeptiert Klasse, Objekt oder Array; Arrays werden nur als serialisierte Daten eingebettet. Optional `alias` und `instructions`.

## Optional streaming debug logging

All five function options arrays (`phore_ai_text`, `phore_ai_struct`,
`phore_ai_struct_array`, `phore_ai_image`, `phore_ai_edit_file`) accept
`debug_log?: bool|\Phore\AiHarness\Logging\LoggerInterface`:

```php
$text = phore_ai_text('Summarize the status', ['debug_log' => true]);
$ai = (new \Phore\AiHarness\PhoreAi())
    ->withLogger(new \Phore\AiHarness\Logging\ConsoleLogger());
```

Default/`false`: no logger, existing non-streaming behavior. `true`: console
logging to STDERR. A custom logger implements `log(LogEvent $event): void`.
Other values (including `null`) are rejected before the API call.
`withLogger()` is immutable; `withLogger(null)` disables it.

With a logger, text/structured requests and callback follow-ups stream;
images remain non-streaming. Output has `[model]` prefixes, buffered complete
lines, tool start/status/duration entries and one final `RunStatistics` event.
Terminal warnings are red unless `NO_COLOR` is set. Tool arguments and known
credential patterns are redacted before custom loggers receive them; results
are represented by byte counts, and raw exception messages are omitted.

Only an explicit `RecoverableToolException` becomes a machine-readable
`ok: false` output, identically with or without logging. All other callback
exceptions and argument decoding/validation/binding errors abort unchanged. Correction
requests count as retries; at most five callback rounds execute. Remaining calls
then raise an exception. Task errors, transport/authentication failures, internal
PHP errors and serialization failures are not retried. Without logging,
existing immediate-error behavior remains unchanged.

`stats` contains `status`, `requests`, `tool_calls`, `errors`, `retries`,
`tokens_in`, `tokens_out`, `tokens_total`, `duration_total`, `duration_api`,
`duration_tools`. Durations use a monotonic clock and seconds. Tokens sum all
available response usage, with `null`/`n/a` if unavailable. The summary is emitted
once in a finally path, also for failures during request preparation or hydration.
