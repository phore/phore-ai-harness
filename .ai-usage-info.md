# AI Usage Info

## Sinn der Library

Eine OpenAI Library ohne externe Abhängigkeiten. Die Verbindung wird mit CURL aufgebaut und nutzt ausschließlich die OpenAI Responses API (`POST /v1/responses`). Unterstützt werden nur GPT-5-Modelle und neuer; `temperature` wird nicht an die API serialisiert.

## Öffentliche Klassen

- `Phore\AiHarness\PhoreAi`: High-Level-Fassade für Prompt- und Tool-Value-Objects. `with()` setzt Prompts und OpenAI-Tools, `withOutput()` setzt ein Ausgabeformat, `withModel()` überschreibt das Default-Modell, `run()` liefert Text, `runImage()` generiert ein Bild als `ImageResultType`, `runCasted(MyDto::class)` nutzt OpenAI Structured Output und hydriert JSON per `phore/schema`.
- `Phore\AiHarness\Client\OpenAiClient`: CURL-Client für nicht-streaming und streaming Responses-API-Aufrufe. Wenn kein API-Key im Constructor übergeben wird, liest der Client den Key über den `Keystore`.
- `Phore\AiHarness\Client\AiRequest`: Request-Value-Object für Responses-API-Payloads; `withOutputSchema()` setzt OpenAI Structured Output (`text.format.json_schema`). Das Feld `tools` kann direkt im Constructor gesetzt werden. `AiRequest::$last` enthält den zuletzt erzeugten Request dieses PHP-Prozesses.
- `Phore\AiHarness\Client\AiResponse`: Response-Value-Object mit Zugriff auf Status, Header, Body, Output-Text und `getUsage(): UsageInfoType` für Tokenverbrauch/Kostenschätzung. `AiResponse::$last` enthält die zuletzt erzeugte Response dieses PHP-Prozesses.
- `Phore\AiHarness\Client\AiRequestSpooler`: verarbeitet mehrere `AiRequest`-Instanzen parallel über `curl_multi`.
- `Phore\AiHarness\Client\AiRequestException`: wird bei CURL-/Kommunikationsfehlern oder HTTP-Fehlerstatus der OpenAI API geworfen und enthält optional die `AiResponse`.
- Prompt-Typen unter `Phore\AiHarness\PromptType`: `TextPrompt`, `SystemPrompt`, `FilePrompt`, `ImagePrompt`, `AudioPrompt`, `StructPrompt`. `TextPrompt::fromFile()`, `SystemPrompt::fromFile()`, `FilePrompt::fromFile()`, `ImagePrompt::fromFile()` und `AudioPrompt::fromFile()` laden Inhalte direkt aus Dateien. `StructPrompt` akzeptiert Klasse, Objekt oder Array; bei Arrays wird kein JSON Schema erzeugt, sondern nur der serialisierte Inhalt eingebettet. Optional sind `alias: 'name'` als Referenzname und `instructions: '...'` zur Behandlung des Structs möglich. `FilePrompt` enthält `contentType`. OpenAI-Content-Sections werden über `Phore\AiHarness\Client\OpenAI\OpenAiPromptToContentConverter` erzeugt (`input_text`, `input_file`, `input_image`, `input_audio`).
- Tool-Typen unter `Phore\AiHarness\ToolType`: `WebAccessTool`, `FileSearchTool`, `CodeInterpreterTool`, `ImageGenerationTool`, `ComputerUseTool`, `McpTool`, `LocalShellTool`. Diese können wie Prompts an `PhoreAi::with()` übergeben werden. `ToolType::toArray($provider)`/`type($provider)` erzeugen die provider-spezifische Tool-Definition; aktuell ist `open_ai` implementiert. `ImageGenerationTool` validiert die Optionen `size` (`auto`, `1024x1024`, `1024x1536`, `1536x1024`), `output_format` (`png`, `jpeg`, `webp`), `quality` (`auto`, `low`, `medium`, `high`) und `background` (`auto`, `transparent`, `opaque`).
- Ausgabeformate unter `Phore\AiHarness\OutputFormat`: `TextOutput`, `StructOutput`, `FileOutput`, `ImageOutput`.
- `Phore\AiHarness\Result\ImageResultType`: Ergebnis von `PhoreAi::runImage()` mit `data`, `contentType`, `fileExtension` und `saveToFile($file)`. Das Extrahieren aus OpenAI-Responses erfolgt über `OpenAiClient::buildImageResponse()`.
- `Phore\AiHarness\Result\UsageInfoType`: Ergebnis von `AiResponse::getUsage()` mit `inputTokens`, `outputTokens`, `totalTokens`, `cachedInputTokens`, `reasoningOutputTokens` sowie geschätzten USD-Kosten (`inputCostUsd`, `outputCostUsd`, `totalCostUsd`).
- `Phore\AiHarness\Helper\Toolkit`: statische Hilfsmethoden für JSON-Encoding/-Decoding von Modelloutput, Instruction-Merging und OpenAI-kompatible Schema-Namen.
- `Phore\AiHarness\Helper\DataUrl`: Helper für Base64-Data-URLs: `new DataUrl($data, $contentType)`, `DataUrl::loadString($dataUrl)`, `tryLoadString()`, `fromFile()` und `toString()`.
- `Phore\AiHarness\Keystore\Keystore`: Singleton für Provider-API-Keys. `addKey($key, $provider = 'open_ai')` setzt Keys manuell; standardmäßig wird `OPENAI_API_KEY`/Provider-ENV oder `/var/run/secrets/open_ai` gelesen. `PhoreAi` nutzt den Keystore, wenn kein Secret im `openai:`-DSN steht.

## Kurzbeispiel

```php
use Phore\AiHarness\Client\AiRequest;
use Phore\AiHarness\Client\OpenAiClient;

$client = new OpenAiClient(); // API-Key kommt aus dem Keystore, falls nicht direkt übergeben
$response = $client->createResponse(AiRequest::text('gpt-5-mini', 'Sag Hallo'));
echo $response->getOutputText();
```

High-Level-Fassade:

```php
use Phore\AiHarness\PhoreAi;
use Phore\AiHarness\PromptType\TextPrompt;

$ai = new PhoreAi('openai:' . getenv('OPENAI_API_KEY'));
$text = $ai
    ->with(new TextPrompt('Sag Hallo'))
    ->run();
```

Casting in ein DTO:

```php
final readonly class AnswerDto { public function __construct(public string $answer) {} }

$dto = $ai
    ->with(new TextPrompt('Antworte kurz.'))
    ->runCasted(AnswerDto::class);
```

Streaming:

```php
$finalResponse = $client->streamResponse(
    AiRequest::text('gpt-5-mini', 'Zähle bis drei'),
    function (array $event): void {
        if (($event['type'] ?? null) === 'response.output_text.delta') {
            echo $event['delta'];
        }
    },
);
```

## E2E-Tests

E2E-Tests gegen die echte OpenAI API liegen unter `e2etests/` und sind nicht Teil der normalen PHPUnit-Suite (`test/`). Manuell ausführbar mit:

```bash
vendor/bin/phpunit -c e2etests/phpunit.xml.dist
```

Der OpenAI-Key wird über `Phore\AiHarness\Keystore\Keystore` geladen.

## Globale Funktionen

- `phore_ai_text($prompts, array $options = []): string`: Kurzform für Textausgaben. Strings werden zu `TextPrompt`; Arrays dürfen Strings, `PromptType` und `ToolType` enthalten. Optionen: `client`, `model`.
- `phore_ai_image($prompts, array $options = []): ImageResultType`: Kurzform für Bildgenerierung. Optionen: `client`, `model`, `size`, `output_format`, `quality`, `background`.
- `phore_ai_struct($prompts, string $className, array $options = []): object`: Kurzform für Structured Output mit Hydration in `$className`. Optionen: `client`, `model`.
- `get_last_ai_request(): ?AiRequest`: liefert `AiRequest::$last`, also den zuletzt in diesem PHP-Prozess erzeugten OpenAI Responses API Request oder `null`.
- `get_last_ai_response(): ?AiResponse`: liefert `AiResponse::$last`, also die zuletzt in diesem PHP-Prozess erzeugte OpenAI Responses API Response oder `null`.
- Die internen Hilfsroutinen der Kurzformen liegen als statische Methoden in `Phore\AiHarness\Helper\Toolkit` (`createAi()`, `normalizePromptItems()`, `hasTool()`, `contentTypeFromImageOutputFormat()`).
